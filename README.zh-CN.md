# ClockTower · Trouble Brewing

![ClockTower · Trouble Brewing](public/cover.png)

一个面向《血染钟楼：暗流涌动》（Blood on the Clocktower: Trouble Brewing）的非官方局域网多人游戏辅助工具。说书人在电脑端运行主机并管理魔典、座位、身份、夜间流程、提名与投票；所有玩家使用手机连接同一局域网，加入房间并实时接收各自可见的信息。

> 当前版本：`v1.0.0`<br>
> 支持人数：5–15 名玩家<br>
> **联机要求：必须联机使用。说书人电脑和所有玩家设备需要连接到同一个局域网。**

## 功能

- 局域网强制联机：说书人作为主机，玩家通过房间码、链接或二维码加入
- 基于 WebSocket 的实时状态同步与断线重连
- 自动或手动分配《暗流涌动》角色
- 私密身份揭示、邪恶阵营信息与恶魔伪装身份
- 说书人魔典、座位排序、状态标记与自定义提醒
- 首夜/其他夜晚顺序及玩家夜间操作同步
- 白天讨论、提名、投票、处决与死亡投票管理
- 撤销、重做、游戏日志、导入与导出
- 黎明及结局演出、房间音效与动画开关
- 中文/英文界面与桌面/移动端响应式布局
- SQLite 房间持久化，以及只读、确定性的说书人提示
- 可安装的 PWA 与可替换的自定义美术资源

## 技术栈

- React 19 + Vite 6
- TypeScript 5.9
- Fastify 5 + WebSocket
- Node.js 内置 SQLite
- pnpm workspace
- Vitest + Playwright + ESLint + Prettier

## 快速开始

### 环境要求

- Node.js 22 或更高版本
- pnpm 11.9.0
- 一台作为主机的说书人电脑
- 与主机处于同一 Wi-Fi 或有线局域网的玩家手机

如果尚未安装 pnpm，可以通过 Corepack 启用：

```bash
corepack enable
corepack prepare pnpm@11.9.0 --activate
```

### 安装与启动

```bash
git clone https://github.com/stefanokratzdisteln-hash/_ClockTower.git
cd _ClockTower
git switch v1.0.0
pnpm install
pnpm dev
```

启动后，本机调试地址为：

- Web 界面：<http://localhost:5173>
- 服务端健康检查：<http://localhost:3000/health>

Windows 用户也可以运行 `start.bat`，但该脚本当前包含本机绝对路径；在其他电脑上使用前需要修改其中的项目目录。

## 局域网联机（必须）

本项目没有离线单人模式。说书人端、玩家端及服务端必须保持网络连接，玩家的身份、夜间行动、提名和投票都会通过局域网实时同步。

### 1. 连接同一个网络

将说书人电脑与所有玩家手机连接到同一个 Wi-Fi 或有线局域网。访客 Wi-Fi、开启客户端隔离的路由器，以及手机蜂窝网络可能会阻止设备之间互相访问。

### 2. 查找说书人电脑的局域网 IP

在 Windows PowerShell 或命令提示符中运行：

```powershell
ipconfig
```

找到当前网络适配器的 `IPv4 Address`，例如 `192.168.1.100`。不要把 `127.0.0.1` 或 `localhost` 发给玩家，这两个地址只代表玩家自己的设备。

### 3. 使用局域网地址打开说书人端

运行 `pnpm dev` 后，说书人应在浏览器中打开：

```text
http://<说书人电脑的局域网 IP>:5173
```

例如：

```text
http://192.168.1.100:5173
```

**说书人必须使用这个局域网地址创建房间。** 玩家链接和二维码会基于当前浏览器地址生成；如果说书人从 `localhost:5173` 创建房间，生成的二维码也会包含 `localhost`，玩家手机将无法连接。

### 4. 让玩家加入

创建房间后，玩家可以：

- 扫描说书人界面显示的二维码；
- 打开说书人复制的玩家链接；
- 先访问 `http://<局域网 IP>:5173`，再输入房间码和座位昵称。

玩家加入后，说书人界面会显示在线状态。游戏期间不要关闭运行 `pnpm dev` 的终端，也不要让主机电脑休眠或切换网络。

### 5. Windows 防火墙

Windows 首次启动服务时可能询问是否允许网络访问，请至少勾选“专用网络”。如果玩家无法打开页面，请检查防火墙是否允许 Node.js。开发模式下，玩家必须能够访问主机的 `5173` 端口，Vite 会在主机内部把 API 与 WebSocket 请求转发到 `3000` 端口：

- `5173`：玩家需要访问的 Web 界面
- `3000`：主机本地运行的 API 与 WebSocket 服务；前后端分离部署时也需要正确开放和配置

### 联机故障排查

| 问题                    | 检查方法                                                  |
| ----------------------- | --------------------------------------------------------- |
| 玩家打不开页面          | 确认使用局域网 IP，而不是 `localhost`；确认设备在同一网络 |
| 二维码打开后无法连接    | 说书人改用局域网地址打开页面，然后重新复制链接或二维码    |
| 页面能打开但状态不更新  | 确认服务端仍在运行，并检查终端报错、防火墙和 WebSocket    |
| 玩家频繁重连            | 关闭手机蜂窝网络自动切换，保持 Wi-Fi 稳定，并禁止主机休眠 |
| 同一 Wi-Fi 仍然无法访问 | 检查路由器是否启用了 AP/客户端隔离或访客网络限制          |

## 游戏流程

1. 所有设备连接同一个局域网，说书人启动项目并通过局域网 IP 打开 Web 界面。
2. 说书人创建房间。
3. 将玩家链接、二维码或房间码发送给玩家。
4. 玩家使用与座位一致的昵称加入房间。
5. 说书人确认所有玩家在线，再自动或手动分配角色。
6. 按界面提示推进身份揭示、首夜、白天、提名、投票与后续夜晚。
7. 游戏结束后公开复盘，或导出当前游戏数据留存。

说书人仍是最终裁定者。规则引擎会校验阶段和操作，但项目不会取代说书人，也没有内置发布版规则全文。

## 常用命令

| 命令                | 用途                                 |
| ------------------- | ------------------------------------ |
| `pnpm dev`          | 同时启动 Web 与服务端开发环境        |
| `pnpm build`        | 构建所有 workspace 包                |
| `pnpm test`         | 运行单元测试与服务端测试             |
| `pnpm test:e2e`     | 构建项目并运行 Playwright 端到端测试 |
| `pnpm typecheck`    | 检查所有 TypeScript 类型             |
| `pnpm lint`         | 运行 ESLint                          |
| `pnpm format:check` | 检查代码格式                         |
| `pnpm format`       | 使用 Prettier 格式化项目             |

首次运行端到端测试前，需要安装 Playwright 浏览器：

```bash
pnpm exec playwright install chromium
```

## 配置

| 环境变量             | 默认值                   | 说明                                        |
| -------------------- | ------------------------ | ------------------------------------------- |
| `PORT`               | `3000`                   | Fastify 服务端端口                          |
| `CLOCKTOWER_DB_PATH` | `data/clocktower.sqlite` | SQLite 数据库路径                           |
| `VITE_API_URL`       | 同源地址                 | Web 端连接的 API 地址；前后端分离部署时设置 |

开发环境下，Vite 会把 `/api` 和 `/ws` 代理到 `localhost:3000`。

## 项目结构

```text
.
├─ apps/
│  ├─ web/              # React Web 与玩家移动端界面
│  └─ server/           # Fastify API、WebSocket 与房间持久化
├─ packages/
│  ├─ rules-engine/     # 游戏状态、阶段、角色与操作校验
│  └─ shared/           # 前后端共享类型
├─ tests/e2e/           # Playwright 多人游戏与双语界面测试
├─ docs/                # 素材规范和规则冲突裁定记录
└─ public/              # 项目图片、音频与演出素材
```

## 自定义美术资源

将自定义素材放入 `apps/web/public/assets/user/`，并严格使用 [`docs/ASSET_SPEC.md`](docs/ASSET_SPEC.md) 中规定的文件名和尺寸。缺少某项素材时，界面会继续使用内置 CSS 或现有资源作为回退。

请勿把按钮文字或界面文案直接绘制在背景图中，以免影响双语显示和响应式布局。

## 数据与安全

- 房间状态保存在本地 SQLite 数据库中，默认文件为 `data/clocktower.sqlite`。
- 会话令牌以摘要形式持久化；玩家只会收到其角色允许查看的信息。
- 当前提示服务是本地、只读且确定性的实现，不会调用外部 AI 网络服务，也不能直接修改游戏状态。
- 本项目尚未提供公网部署所需的完整账户系统、限流或反向代理配置。公开部署前请自行补充 HTTPS、访问控制、备份和监控。
